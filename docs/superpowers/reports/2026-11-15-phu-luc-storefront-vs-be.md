## 8. The five differences most likely to break the storefront first

1. **Parse failures on every DTO (X1 + row 1/4/21-23 + template).** zod demands keys the BE omits (`projectId`, `previewUrl`, `lastReturn`, `approval`, `description`, `maxColors`, `allowedFontCodes`, `notInProject`, ...) and needs a `DesignDto` the BE does not send (`product{}`, `variant{}`, `project{}`, `createdAt`, `approval`). `designPageDtoSchema` parses the whole page, so one design makes the list screen fail (`schemas.ts:34-61`, `DTO/DesignDraftResponse.java:18-23`).
2. **Paths and methods that return 404/405 at once:** `POST /designs` (BE `/designs/mine`, plus `productId`+`templateCode`), `PATCH`/`DELETE /designs/{id}`, `GET .../assets/{id}/url`, `/design-projects/{id}/designs` (GET), `.../library*`, `PATCH /design-projects/{id}`, `/designs/{id}/files`, `/submissions`, `/submission-uploads` (`api-designs.ts:48,60,73`, `api-document.ts:73`, `api-projects.ts:65,82,112`, `api-library.ts`, `api-submission.ts:49,94`).
3. **The studio cannot open: `/print-config` does not exist** and `/customization` has a different shape (`templates[]`, no `template` wrapper, no `fileRules`/`variantStatus`/`product`); a design on a replaced or deactivated template needs `/designs/{id}/template` instead (`api-submission.ts:105`, `CatalogCustomizationResponse.java:14,22-25`, `CatalogCustomizationService.java:81`). Also `model3d` is silently dropped (2D/parametric fallback) unless the template's surface map is complete and named `print:<CODE>`, which the BE does not enforce.
4. **Submit flow:** the one-call `/submissions` does not exist; the BE needs save -> 3 artifact uploads with `documentChecksum` (version moves per upload) -> re-read version -> `technical-review-requests`; server preflight and template-version binding add `DESIGN_FILES_OUTDATED` and PDF/geometry checks the storefront never handles (`api-submission.ts:43-51`, `DesignSubmissionService.java:163-216`). Batch submit has the same dependency (`DesignBatchSubmissionService.java:96-134`).
5. **Error handling stops reacting:** stale version is `CONFLICT` not `VERSION_CONFLICT`, draft limit/library full/project errors are 409 `DESIGN_*` not 422 codes, and preflight issues use `rule` with English text and no `level`, so `preflightIssuesOf` returns `null` and the issue list shows nothing (`errors.ts:12-43,83-104`, `ErrorCode.java:863-914,1004-1009`, `LayoutPreflight.java:420-436`). A stale member of a batch cannot be named at all.
